# Multi-Shot Prompt

本 Skill 的最终产物始终是一个完整提示词，内部固定分为四个部分：视频梗概、影片质感、素材锁定、最长30秒分镜。四部分可分开编译和校验，但不得视为四个提示词，也不得分开作为最终产物交付。只要任务要求创建或修改提示词，就把四部分按固定顺序放入同一个 txt 代码块，以一个可整体复制的大提示词交付。执行清单、成片审查和返修是按需加载的下游工具，不参与主提示词写作。

## 先选择执行模式

每次创建或修改四部分完整提示词前，必须显式选择且只选择一种模式：

- `standalone_mode`：保留 v4 的独立创作能力。可根据用户 brief 决定素材、质感、叙事、镜头和表演。
- `managed_mode`：项目系统托管模式。只接收 Master Director 已批准的 `shot_brief`、锁定素材事实和已批准 Style 规则；只做格式翻译与目标视频生成服务的可执行化，不重新导演。

读取 `references/execution_modes.md`。缺少模式时停止并返回 `E_EXECUTION_MODE_REQUIRED`。项目 Agent 包只能调用 `managed_mode`。

## 可选内容模式

需要生成自然、真实、像虚拟成年模特本人随手录制的日常自拍视频时，可在权限模式之外显式启用：

```text
content_mode: realistic_daily_selfie_mode
```

该模式不替代 `standalone_mode` / `managed_mode`，也不替代 `I2V` / `FLF2V` 等生成模式。启用后读取 `references/realistic_daily_selfie_mode.md` 与 `checklists/realistic_daily_selfie_qc.md`。默认要求一张起点截图并路由到 `I2V`；没有起点图时返回 `E_DAILY_SELFIE_START_IMAGE_REQUIRED`。在 `managed_mode` 中，只有已批准输入明确指定该内容模式时才能启用。

## 权威模型

1. **第一部分·视频梗概**：用1至3句总体说明要生成一个什么样的视频。
2. **第二部分·影片质感**：声明素材如何被拍摄和呈现。
3. **第三部分·素材锁定**：按照场景、角色、道具分组，写明对应参考文件与长期保持的实体特征。
4. **第四部分·30秒分镜**：声明当前片段发生什么，以及镜头、表演、光影执行和时间。
5. **执行清单**：绑定生成模式、平台素材和四部分内容指纹，不改写提示词。
6. **成片审查与返修**：记录真实结果，并基于证据进行单变量修复。

视频梗概是后三部分的派生摘要，不是额外语义权威；冲突时必须改写梗概。素材身份冲突时以素材锁定为准；风格、摄影、成像或光色冲突时以影片质感为准；当前动作、镜头和时间由分镜决定。下游不能反向修改上游。在 `managed_mode` 中，四部分内容的语义权威仍属于 Master Director 和项目 Style Skill，本 Skill 只拥有平台格式与可执行性判断权。

## 顶层任务路由

按以下优先级工作：

1. 用户只要求讨论或审查：给出结论，不生成提示词。
2. 用户提交生成结果：创建成片审查记录。
3. 用户要求修复失败结果：读取 repair take，创建返修模块。
4. 用户要求执行、延长、编辑、首尾帧或参考素材生成：读取一个完整提示词中的四部分原文，创建执行清单。
5. 用户要求新建提示词：先编译素材锁定、影片质感和分镜，再据此写简短视频梗概；最终按视频梗概 → 影片质感 → 素材锁定 → 分镜的顺序一次性交付整个提示词。
6. 用户要求修改其中一部分：修改视频梗概时只改梗概；修改后三部分之一时，只改指定的具体部分，另外两个具体部分逐字保持，并仅在失配时同步改写派生的视频梗概。最后在同一个 txt 代码块中交付完整提示词。
7. 创建或修改时缺少任一必需部分的原文，且当前模式不允许重建它：要求提供缺失原文，不交付局部提示词。

跨对话缺少任一上游原文时，不凭记忆复原。要求提供已锁定原文，或从缺失阶段重新创建；在四部分齐全前不输出局部提示词。

## Managed Mode 门禁

进入 `managed_mode` 时：

1. 读取 `templates/managed_input_template.json` 与 `references/managed_input_contract.md`。
2. 校验 `approval.status=approved`、`approval.authority=master-director-agent` 和 `shot_brief_hash`。
3. 校验素材事实和 Style 规则均为 locked/approved 且绑定 SHA-256。
4. 校验 `shot_brief` 已确定剧情目的、镜头数、连续时间轴、动作顺序、表演、调度、机位意图、构图硬锁和最终落点。
5. 只把批准内容映射到四部分模板；视频梗概只能摘要已批准内容；不读取 `references/director_method.md`。
6. 若输入缺失、未批准、冲突或要求重新导演，停止并输出一个错误码与缺失字段，不生成候选方案。

禁止本 Skill 在 `managed_mode` 中：

- 新增或删除剧情事件、镜头、动作、角色、道具或台词。
- 改变镜头数量、持续时间、动作顺序、表演递进、场面调度、机位意图、构图硬锁或落点。
- 用自身偏好覆盖 Style 规则，或把内容资产提炼成新的项目风格。
- 通过“优化”“平台适配”暗中改写已批准决定。

允许的变换仅限：字段归位、同义压缩、语法规范化、真实参考文件与平台槽位的机械映射，以及不改变批准意图的生成可执行性风险提示。风险提示必须阻断并返回上游，不得自行改方案。

## 不可违背的规则

- 中文为默认输出语言，除非用户指定其他语言。
- 视频梗概使用1至3句简短描述，不展开成素材清单、参数表或时间线。
- 素材锁定与影片质感分别不超过1000字；分镜不超过5000字。
- 整段分镜从0秒连续计时，总时长不超过30秒；每镜内的时间段沿用全片绝对秒数。
- 分镜按已批准内容或 standalone 内容密度使用1至9镜；时间使用连续整数秒，前镜结束时间等于后镜开始时间。
- 影片质感必须按 `影像风格：`、`摄影偏好：`、`材质与氛围：`、`光影与色彩：` 四个独立字段依次输出，每字段写入可执行且非空的描述。不能压缩为无字段的整段文字。
- 素材锁定固定使用 `场景：`、`角色：`、`道具：` 三个分组。每份真实素材直接以 `@文件名.格式：` 起首，在对应条目内写明外观、身份、用途和跨镜保持项；角色还须说明稳定的性格与表演特征。角色音色文件归属相应角色。影片质感只含风格、摄影、氛围、光影与色彩。
- 分镜不得出现设备参数、焦距、光圈、快门、ISO、滤镜参数、单独角度或总表演顺序栏目。
- 每镜依次输出 `视频内容：`、`拍摄手法：`、`光影执行：`、`声音：`、`台词：`、`结束落点：`。`视频内容` 按动作与视觉变化划分一个或多个连续时间段，用 `[起始秒]—[结束秒]秒：连续画面描述` 写事件发生顺序；时间段可用小数并完整覆盖本镜。背景、人物、道具、表演和必要视听变化融入连续文字，当前状态自然推进至镜头落点。
- 素材引用采用已提供且可读取的真实 `@文件名.格式`，保留完整原始文件名与扩展名；人物、道具引用可在分镜的动作与台词中复用。场景参考图只在 `素材锁定 > 场景` 中绑定，分镜逐镜用自然语言描述环境画面、空间关系和环境动态，不引用 `@场景文件名`。没有对应参考时以普通文字定义实体；不虚构附件。平台槽位由执行层据实映射。
- 对白在 `视频内容` 的实际说话时刻完整写成 `@人物A.png说（@人物A音色.mp3）：“台词内容”`，与当时动作、表情和听者反应相衔接。每镜另保留 `台词：`，按发生顺序逐行复写正文中的同一句台词；说话者、音色、文字、中文双引号与次数逐一一致，这一栏是索引，对应正文中的同一次说话。无人讲话时写 `台词：无`。未提供音色文件时使用 `@人物A.png说：“台词内容”`；未提供人物图时以已锁定的角色名称代替人物引用，已绑定的音色随角色使用。
- 画幅是内部项目设置和执行参数，不增加到四部分可见模板。
- 默认无背景音乐；环境声和动作音归 `声音`，需要同步画面时在对应时间段交代发生时点；对白同时写入 `视频内容` 与 `台词`。
- 内部判断、QC过程、迭代说明和角色分析不作为最终栏目。
- 启用 `realistic_daily_selfie_mode` 且用户与起点截图都未指定其他拍摄来源时，默认使用手机前置摄像头自拍。明确要求镜面自拍、反射构图或第三方跟拍时可以采用，但必须在提示词中声明拍摄来源并保持机位物理一致。
- 启用 `realistic_daily_selfie_mode` 时，必须在 `front_camera_selfie`、`mirror_selfie`、`third_party_capture` 中选择且只选择一个 `capture_mode`。摄影机归属、拍摄设备可见性、人物视线和运镜来源必须同时服从该模式；禁止把同一部手机同时写成成片摄影机与普通画面内道具。
- 起点截图若与明确指定的 `capture_mode` 冲突，停止并返回 `E_CAPTURE_SOURCE_CONFLICT`，不得用隐形第三方摄影机消解矛盾。
- `realistic_daily_selfie_mode` 只支持明确成年的虚拟模特，或已通过肖像授权门的真人；内容可以成熟、性感但必须非露骨。
- `realistic_daily_selfie_mode` 先锁定一个开场就可读的单一视觉钩子，再安排一个主运动和最多两个辅助变化；不为了构成小故事而堆叠多个整理、移动、对视和微笑任务。

## 四部分工作流

### 视频梗概

1. 先完成或读取素材锁定、影片质感和分镜。
2. 用1至3句概括主体、核心事件、整体气质和最终观看印象。
3. 删除逐项素材清单、影像参数、逐镜时间线和无下游依据的新决定。
4. 运行视频梗概QC；将结果放在完整提示词最开头，不单独交付。

### 影片质感

1. 读取素材锁定，但不复述其具体身份和清单。
2. 建立风格类型、摄影偏好、整体质感与氛围、光影与色彩。
3. 把设备或媒介来源转译为稳定的摄影行为，不提前安排单镜动作。
4. 删除场景拓扑、角色、道具、叙事和时间信息。
5. 用质感模板严格输出 `影像风格：` → `摄影偏好：` → `材质与氛围：` → `光影与色彩：` 四个独立且非空字段，全部字段完成后运行质感QC；将结果作为完整提示词的第二部分，不单独交付。

### 素材锁定

1. 区分长期资产与当前片段状态。
2. 锁定场景拓扑、方向、固定环境物件和物理规则。
3. 锁定角色与道具的身份、外观、材质和识别特征。
4. 使用三个固定分组：`场景：`、`角色：`、`道具：`。有参考图时，以 `@真实文件名.扩展名：` 作为对应条目的起点，并具体描述可见外观、结构、身份、保持项及参考用途。角色条目补充稳定性格/表演特征；如有授权音色文件，在同一角色条目中绑定 `@音色文件名.扩展名`。无参考的实体用普通名称表述，不设单独的“参考素材”目录。
5. 删除与身份无关的摄影、动作和时间信息；影像风格及具体摄影规则归入影片质感。
6. 用素材模板编译并运行素材QC；将结果作为完整提示词的第三部分，不单独交付。

### 30秒分镜

1. 读取两个锁定模块，提取不可漂移的素材与呈现锚点。
2. `standalone_mode` 决定总叙事、观看顺序、必要镜头和最终落点；`managed_mode` 逐项继承 `shot_brief`，不得重做这些决定。
3. `standalone_mode` 分配连续整数时间并设计镜头；`managed_mode` 只把批准的时间轴和机位决定映射到模板。
4. 每镜在 `视频内容：` 下按全片时间顺序写连续画面。根据动作节奏划分一个或多个时间段，逐段交代可见背景、主体行为和前后状态的衔接；场景以自然语言描述，角色与道具沿用真实 `@` 文件名。
5. 在实际开口的时间段嵌入完整的 `@人物A.png说（@人物A音色.mp3）：“台词内容”`，并在本镜 `台词：` 下按相同顺序逐句复写。无对白填 `台词：无`；核对两处说话者、音色、语句、引号与次数一致。
6. 不存在独立辅光或轮廓光时明确写无，不虚构三点布光。
7. 运行分镜、继承及对应模式QC；将结果作为完整提示词的第四部分。
8. 根据素材锁定、影片质感与分镜生成视频梗概，再按视频梗概 → 影片质感 → 素材锁定 → 分镜的顺序组装四部分，只交付一个 txt 代码块中的完整提示词。

启用 `realistic_daily_selfie_mode` 时，以上四部分继续作为一个提示词整体交付，但分镜默认收敛为从起点截图连续展开的单个10秒镜头。影片质感的“摄影偏好”和分镜的“拍摄手法”必须各写一次完全一致的 `摄影机身份：[capture_mode]`；视频内容的相应时间段写清手部占用。摄影机归属、拍摄设备可见性、视线、动作、轻微广角、自动对焦和自动曝光必须通过专项QC。

## 按需生产链

### 执行清单

- 选择 `T2V`、`I2V`、`R2V`、`FLF2V`、`EXTEND` 或 `EDIT`。
- 分别绑定视频梗概、素材锁定、影片质感和分镜的ID、版本与SHA-256。
- 固定声明 `verbatim_concat`，顺序为 `video_summary → film_texture → material_lock → storyboard`。
- 不创建第四份执行提示词；沿用提示词中的真实 `@文件名.格式`，需要平台数字槽位时，仅在执行层根据真实附件清单机械映射，保存对应关系。
- 保留素材转移边界、模式专项合同、音频节拍、安全与授权门。

### 成片审查与续写

- 记录 take ID、尝试编号、媒体引用、指纹、审查来源和时间。
- 只有 `observed + accepted + test_only:false` 且证据完整的 take 可以成为正式下一段起点。
- `simulated` 只用于 `examples/validation-fixtures/`，不得进入生产连续性链。

### 单变量返修

- 从 repair take 选择一个主要失败分类并引用可见证据。
- 分别列出必须保持的素材锁定、影片质感和已正确分镜内容。
- 只允许一个主改变变量；返修后必须产生新 take 并重新审查。

## 修改与冲突

- 修改视频梗概：只替换第一部分，后三部分原文不变；交付四部分完整提示词，代码块后仅追加 `需要重新校验：执行清单。`
- 修改影片质感：替换第二部分，其他三部分原文不变；交付四部分完整提示词，代码块后仅追加 `需要重新校验：视频梗概、既有分镜、执行清单。`
- 修改素材锁定：替换第三部分，其他模块保留不受影响的原文；角色/道具/音色文件名变化时同步更新相关分镜中的引用，场景参考变更时重新检查分镜背景的文字描述；交付完整提示词，代码块后仅追加 `需要重新校验：视频梗概、影片质感、既有分镜、执行清单。`
- 修改或替换分镜：替换第四部分并从0秒计时，前三部分中视频梗概必须与新分镜一致；交付四部分完整提示词，代码块后仅追加 `需要重新校验：视频梗概、执行清单。`
- 修改执行方式：四部分原文不变，只替换执行清单。
- 发生冲突：标明所属层级；能局部消解时只改下游，不能消解时停止冲突输出。
- `managed_mode` 的任何语义变更都返回 Master Director 或项目 Style Skill；本 Skill 不得先改后报。

## 最终输出

- 创建或修改提示词时，最终只输出一个 txt 代码块。
- 该代码块中固定依次放置视频梗概、影片质感、素材锁定、分镜四个部分；四部分合起来才是一个提示词。
- 禁止把任一部分单独称为或交付为一个提示词；禁止用四个代码块分开交付。
- 执行清单、成片审查和返修仅在明确要求对应任务时单独输出。
- 修改任务只允许在代码块后追加规定的单行 `需要重新校验` 状态；除此之外不追加分析、修改总结或可选方案。
- managed 阻断只输出错误码、字段路径和返回的上游；不得附带未经批准的候选内容。
- 未获得真实生成证据时保持 `Not-tested: live video generation`，不得用结构校验冒充出片质量。
