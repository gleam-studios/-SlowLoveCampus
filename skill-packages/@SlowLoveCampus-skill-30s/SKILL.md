# @SlowLoveCampus-30s

由当前接收本包的 Agent 完成：**一句话剧情 → 匹配素材并输出完整视频提示词，结束。** 创作由当前 Agent 完成，不调用其他模型，不绑定前端或 Codex CLI。显示名为 `@SlowLoveCampus-30s`，兼容客户端发现的内部标识为 `slowlove-campus-30s`。

## 入口与范围

- 将 `BUNDLE` 设为**当前这份 SKILL.md 所在目录的真实绝对路径**，`MS="$BUNDLE/skills/multi-shot-prompt"`。全部资源由包内路径定位；可放在含空格和中文的任意目录。
- 先读 [创作总纲](references/创作总纲.md)。默认一次、30 秒、9:16；角色均为二十多岁的成年人，内容非露骨，所有实际台词必须英文。
- 需要文件读写和**实际查看图片**的能力；辅助检查脚本只依赖 Python 3.10+ 标准库，无第三方依赖。无需视频平台账户、API Key 或视频生成工具。
- 用户要求执行本包完整流程，即依次完成下面两步，不增加逐步审批。只要求一句话剧情时在第一步停止。交付完整提示词后必须结束，不构造生成任务、不上传素材、不调用生成接口、不生成或下载视频，也不追加审片、剪辑、返修或发布。
- 只使用包内总纲、素材和提示词子 Skill；不读取原机器的项目、共享技能库或旧聊天。每次从零创作，历史只允许使用简短活动排除标签，不读往期剧情、完整提示词、分镜或成片来创作。

## 执行准备

运行只读、离线检查：

```bash
python3 "$BUNDLE/scripts/workspace.py" check
```

创建独立工作实例（如实标记当前 Agent／模型，不知道就填 `unknown`，不要切换模型）：

```bash
python3 "$BUNDLE/scripts/workspace.py" prepare --agent "当前Agent名称" --model "当前模型名称" --count 1
```

命令返回 `id`、`work_dir`、`output_dir` 和 `excluded_activities`。后续 `RUN_ID`、`WORK`、`OUT` 使用此次 JSON 的真实值，输出目录用于存放最终提示词。默认写在包内 `runs/<id>/`；安装位置不可写时，在脚本子命令之前加 `--workspace /实际可写目录`，后续保持同一个目录。

## 第一步：一句话剧情

创作指令：

> 想一个男男GAY 面向BL 的双人剧情，适合社媒，短视频，居家，日常，甜蜜，暧昧。一句话。

根据 30 秒总纲独立写一句话，概括日常情境、主要事件的发展、双方回应和最终落点，保存为 `$WORK/story.txt`。允许多个因果相连的小事件，不把一句话限制为一个瞬间动作，也不堆叠无关情节。只用活动标签排除重复，不将历史文本作为灵感。候选活动与排除清单同义也算重复；重新想新活动，不以换道具、地点或台词冒充新创意。

记录本轮简短日常活动名称（替换示意文字，不记录人物、台词、完整互动或分镜）：

```bash
python3 "$BUNDLE/scripts/workspace.py" activity --run-id "$RUN_ID" --name "本轮实际活动"
```

若提示活动已使用，回到本步重新构思。脚本只做规范化后的精确标签占用检查，**语义排重由当前 Agent 完成**。

## 第二步：素材与完整提示词

读取 [包内 multi-shot-prompt](skills/multi-shot-prompt/SKILL.md)，显式选择 `execution_mode: standalone_mode`，按需读取其模板、规则和清单。本包直接授权当前 Agent 独立创作，不建立 Master Director 的 managed 托管／审批链。不默认启用需要起点截图的专项自拍模式。

从 `$BUNDLE/assets/` 选择并**实际查看**两位角色、场景及服装参考，按需绑定角色音色。素材清单见 [ASSETS.json](ASSETS.json)，文件清单和指纹不能代替看图。素材必须真实可读取，保留完整中文原始文件名及扩展名；不虚构附件。没有相应参考的道具用普通文字定义，不擅自制作新资产。

按子 Skill 编写**一个完整提示词**，固定顺序为：视频梗概 → 影片质感 → 素材锁定 → 分镜。连续分镜总长默认 30 秒，9:16 作为内部创作设置，不增加到子 Skill 的可见模板。说明文字可中文；实际台词全部英文，分镜正文与台词索引逐句一致。禁止套用或改写历史提示词。

按 30 秒的内容容量展开剧情，允许更多动作、镜头、简短对白和关联小情节。先设计可持续发展的行动与回应，再分配连续时间；每次镜头变化应呈现新的动作、细节、反应或关系变化。镜头数由故事决定，不硬套固定段落和秒数，不把 15 秒瞬间放慢、重复或单纯增加切镜来凑 30 秒。保持手机随拍、自然光和松弛生活感，核对跨镜空间、道具及人物动作衔接。

保存 `$OUT/prompt.txt`（完整四部分纯文本，不含包裹代码围栏），将选中素材的真实路径、引用名与用途保存到 `$WORK/assets.json`。按子 Skill 的格式、素材绑定与对白规则检查：

```bash
python3 "$MS/scripts/validate_skill_contract.py" --prompt "$OUT/prompt.txt" --prompt-only
```

失败先修当前提示词。检查只验证文本结构、时间边界、引用和对白一致性，不代表已经验证视频效果。不要读取或执行子 Skill 中的生成执行清单、平台提交、成片审查或返修流程。

**最终只交付一个 txt 代码块中的完整提示词；支持文件附件的宿主可同时交付 prompt.txt。不要追加视频任务参数、API 配置或任何生成操作。到此结束。**

## 多次与模型对比

- 用户指定次数时接受 1–3 次；`prepare --count 3` 只创建三个独立工作实例，不会启动模型或 Agent。
- 宿主支持独立并行 Agent 时，将本 SKILL.md 与各自实例路径分别交给三个隔离会话，各完成两步并输出自己的 prompt.txt。不支持时如实说明，只能顺序执行或由用户分别启动；不要把一个会话连续写三份结果称为三个独立会话。
- 每位执行者只写自己的目录；开始创作前用 `context --run-id "$RUN_ID"` 获取最新活动排除标签，登记活动时重新核对。
- 对比模型时，用不同 `--workspace` 保持相同初始历史条件，总纲、资产、时长、画幅一致；保留执行者名称，不预设或切换模型，不携带其他模型的创作结果作为参考。
